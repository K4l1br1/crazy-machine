## 1 Введение

Настоящее техническое задание устанавливает требования к разработке программного продукта
«Торнадочайник-3000» (далее — Программа). Программа представляет собой учебный симулятор необычного
транспортного средства стихии «Воздух» в двумерной системе координат с учётом высоты полёта, запаса энергии
и специальных способностей.

По замыслу транспортное средство имеет форму гигантского летающего чайника. Вместо обычного двигателя оно
использует воздушные потоки, поглощает облака для пополнения энергии и способно перемещаться через
торнадо-портал. Необычные свойства реализуются как детерминированные правила симуляции, а не как управление
реальным транспортом.

## 2 Основания для разработки

Основанием является учебное задание по дисциплине «Сборка, тестирование и верификация программного
продукта» на тему «Разработка безумного транспортного средства». Транспортное средство относится к стихии
«Воздух» в соответствии с распределением ролей учебной группы БСБО-16-23.

## 3 Назначение разработки

### 3.1 Функциональное назначение

Программа предназначена для моделирования состояния воздушного транспортного средства и выполнения команд
взлёта, перемещения, изменения высоты, поглощения облаков, создания торнадо-портала, приземления и
подзарядки аплодисментами.

### 3.2 Эксплуатационное назначение

Программа должна запускаться на персональном компьютере без доступа к сети Интернет и предоставлять

командной строки, не заменяющий основной программный интерфейс.

## 4 Требования к программе

### 4.1 Требования к функциональным характеристикам

#### 4.1.1 Модель состояния

Единицами измерения являются метры для координат и высоты, а также условные единицы для энергии.
Состояние объекта описывается следующими величинами:

| Поле | Смысл | Допустимые значения |
|---|---|---|
| `x` | горизонтальная координата по оси X | целое число; допускаются отрицательные значения, границы мира не моделируются (ФТ-02) |
| `y` | горизонтальная координата по оси Y | целое число; допускаются отрицательные значения, границы мира не моделируются (ФТ-02) |
| `altitude` | высота над землёй | целое число от 0 до 100 |
| `energy` | запас энергии | целое число от 0 до 100 |
| `clouds` | текущий запас поглощённых, но ещё не израсходованных облаков | целое число от 0 до 3 |
| `is_airborne` | признак нахождения в полёте | `True` при `altitude > 0`, иначе `False` |

**ФТ-01.** При создании транспортного средства начальное состояние должно быть:
`x = 0`, `y = 0`, `altitude = 0`, `energy = 60`, `clouds = 0`, `is_airborne = False`.

**ФТ-02.** Для изменения состояния должны использоваться только команды, определённые настоящим ТЗ.
Координаты `x` и `y` могут принимать отрицательные значения. Географическая карта, границы мира и физические
столкновения не моделируются.

**ФТ-03.** При ошибке вызова ни одно поле состояния не должно изменяться. Все успешные команды изменения
состояния должны возвращать `None`.

#### 4.1.2 Основные команды

**ФТ-04.** Команда `take_off()` выполняет взлёт. Допускается только на земле (`altitude = 0`) при `energy`
не менее 10. После выполнения `altitude = 10`, `energy` уменьшается на 10, остальные параметры не изменяются.

**ФТ-05.** Команда `move(dx, dy)` осуществляет горизонтальное перемещение в полёте. Аргументы `dx` и `dy`
должны быть целыми числами от −20 до 20 включительно; запрещено одновременное равенство `dx = 0` и `dy = 0`.
Расход энергии равен `|dx| + |dy|`. При достаточном запасе энергии координаты увеличиваются на соответствующие
значения, `energy` уменьшается на величину расхода. Высота не меняется.

**ФТ-06.** Команда `ascend(meters)` увеличивает высоту только в полёте. Аргумент `meters` должен быть целым
числом от 1 до 30 включительно. Новая высота не должна превышать 100. Расход энергии равен округлённому вверх
значению `meters / 5`. Например, подъём на 11 м требует 3 единицы энергии.

**ФТ-07.** Команда `descend(meters)` снижает высоту только в полёте. Аргумент `meters` должен быть целым числом
от 1 до 30 включительно. Новая высота не может быть меньше 10. Снижение не расходует энергию. Для перехода
на землю используется отдельная команда `land()`.

**ФТ-08.** Команда `eat_cloud()` доступна только в полёте при `altitude` не менее 20 и `clouds` менее 3.
Команда увеличивает `clouds` на 1 и `energy` на 15, но не выше 100. Поглощение облака не изменяет координаты
и высоту. Наличие реальных облаков в пространстве не моделируется.

`clouds` — расходуемый запас, а не суммарный счётчик поглощений за полёт: портал расходует два облака, после
чего запас можно снова пополнять в том же полёте. Ограничения на общее число поглощений за полёт нет.

Пример на новом экземпляре: `take_off()`; `ascend(20)`; `eat_cloud()` три раза; `tornado_portal(1, 1)`;
`eat_cloud()` приводит к `x=1`, `y=1`, `altitude=30`, `energy=81`, `clouds=2`, `is_airborne=True`.
Портал израсходовал два облака, и последнее поглощение снова пополнило запас в том же полёте.

**ФТ-09.** Команда `tornado_portal(dx, dy)` выполняет мгновенное перемещение в воздушном портале. Аргументы
должны быть целыми числами от −100 до 100 включительно, при этом хотя бы один аргумент отличен от нуля.
Команда доступна только в полёте при `altitude` не менее 30, `clouds` не менее 2 и `energy` не менее 25.
После выполнения координаты изменяются на `dx` и `dy`, `energy` уменьшается на 25, `clouds` уменьшается на 2,
высота не изменяется.

**ФТ-10.** Команда `land()` выполняет посадку из любого состояния полёта. После выполнения `altitude = 0`,
`clouds = 0`, `is_airborne = False`. Координаты и запас энергии остаются прежними. Повторная посадка на земле
запрещена.

**ФТ-11.** Команда `applause(count)` моделирует зарядку чайника аплодисментами. Допускается только на земле;
аргумент `count` должен быть целым числом от 1 до 10 включительно. После выполнения `energy` увеличивается на
`5 × count`, но не более 100. Прочие поля не изменяются.

**ФТ-12.** Команда `get_state()` возвращает новый словарь Python с ключами `x`, `y`, `altitude`, `energy`,
`clouds`, `is_airborne` и текущими значениями состояния. Изменение возвращённого словаря не должно менять
внутреннее состояние объекта. Каждый вызов возвращает отдельный независимый словарь: два последовательных
снимка являются разными объектами, а ранее выданный снимок не изменяется последующими командами.

#### 4.1.3 Программный интерфейс и обработка ошибок

**ФТ-13.** Основной класс должен иметь имя `TornadoTeapot` и размещаться в модуле `tornado_teapot.py`. Объект
должен создаваться вызовом `TornadoTeapot()` без обязательных аргументов. Названия методов и аргументов должны
совпадать с указанными в пунктах ФТ-04 — ФТ-12.

**ФТ-14.** Не допускаются аргументы типа `bool`, `float`, `str` и иные значения, не являющиеся целыми числами
типа `int`, для методов с числовыми параметрами. Для некорректного типа, выхода аргумента за установленные
границы или нулевого вектора перемещения должно возникать исключение `ValueError`.

**ФТ-15.** При нарушении условий состояния или нехватке энергии и облаков должны возникать доменные
исключения из модуля `tornado_errors.py`:

- `TornadoTeapotError` — базовый тип отказов, наследуется от `Exception`, а не от `RuntimeError`;
- `InvalidStateError` — команда недопустима при текущем состоянии;
- `InsufficientResourcesError` — для команды не хватает энергии или запаса облаков.

Оба производных типа наследуются от `TornadoTeapotError` и импортируются из `tornado_errors`. Условия
проверяются в следующем порядке: корректность аргументов (`ValueError`), допустимость текущего состояния
(`InvalidStateError`), достаточность ресурсов (`InsufficientResourcesError`).
При одновременном нарушении состояния и нехватке ресурсов приоритет имеет
`InvalidStateError`. Для `tornado_portal` любой недостаток ресурсов (энергия менее 25 или облаков менее 2)
выражается одним `InsufficientResourcesError`. Текст исключения не является частью обязательного интерфейса.

| Команда | `InvalidStateError` | `InsufficientResourcesError` |
|---|---|---|
| `take_off()` | уже в полёте | `energy < 10` |
| `move(dx, dy)` | не в полёте | `energy < \|dx\| + \|dy\|` |
| `ascend(meters)` | не в полёте; новая высота выше 100 | `energy < ceil(meters / 5)` |
| `descend(meters)` | не в полёте; новая высота ниже 10 | — |
| `eat_cloud()` | не в полёте; `altitude < 20`; `clouds = 3` | — |
| `tornado_portal(dx, dy)` | не в полёте; `altitude < 30` | `energy < 25` или `clouds < 2` |
| `land()` | уже на земле | — |
| `applause(count)` | в полёте | — |

**ФТ-16.** Программа не должна использовать случайные числа при вычислении состояния, сетевые обращения и
внешние сервисы. Одинаковая последовательность команд на одинаковом начальном состоянии должна приводить
к одинаковому результату.

#### 4.1.4 Ограничения первой версии

отдельное расширение и требует дополнительных требований.

## Приложение А (обязательное). Приёмочные сценарии

Каждый сценарий выполняется на новом экземпляре `TornadoTeapot`, если в исходных условиях не указана
последовательность подготовки. Значения энергии в описаниях приведены в условных единицах. Под «без изменения
состояния» понимается полное совпадение словарей `get_state()` до и после ошибочного вызова.

**ПТ-01. Начальная инициализация**

Действия: создать `TornadoTeapot()`.

Ожидаемый результат: `get_state()` возвращает `x=0`, `y=0`, `altitude=0`, `energy=60`, `clouds=0`,
`is_airborne=False`.

**ПТ-02. Взлёт**

Действия: вызвать `take_off()`.

Ожидаемый результат: `altitude=10`, `energy=50`, `is_airborne=True`; остальные значения исходные.

**ПТ-03. Повторный взлёт**

Действия: вызвать `take_off()`, затем `take_off()` ещё раз.

## Приложение Б (справочное). Пример использования

Следующая последовательность демонстрирует согласованное поведение транспортного средства и может служить
основой для автоматизированного теста.

```python
from tornado_teapot import TornadoTeapot

teapot = TornadoTeapot()
teapot.take_off()              # высота 10, энергия 50
teapot.ascend(20)              # высота 30, энергия 46
teapot.eat_cloud()             # 1 облако, энергия 61
teapot.eat_cloud()             # 2 облака, энергия 76
teapot.tornado_portal(70, -40) # x=70, y=-40, энергия 51
teapot.land()                  # высота 0, облака 0
print(teapot.get_state())
```

Ожидаемый вывод:

```python
{'x': 70, 'y': -40, 'altitude': 0, 'energy': 51, 'clouds': 0, 'is_airborne': False}
```
